# AI Agent for WhereToPublish Data Maintenance

The WhereToPublish project uses a monthly GitHub Actions pipeline to pull curated journal data from Google Sheets, enrich it with external datasets (Scimago, OpenAPC, DOAJ, etc.), clean and deduplicate it, and output CSVs for the website【25†L348-L355】.  In our plan, the AI agent would **augment** this pipeline: it would read the existing Google Sheets (via the Google Sheets API), identify missing or out-of-date fields (e.g. APCs, open-access status, publisher), search the web to fill gaps, and write suggested corrections back into the sheet (for human review).  These suggestions would then be reviewed by the team before being incorporated into the official data and rerun through the existing scripts【25†L348-L355】【7†L210-L218】.  In summary:

- **Current Pipeline:** Google Sheets (manual curation) → `download_csv.sh` → `data_extracted/*.csv` → `update_extracted.py` (join with external sources) → `data_process.py` (clean/dedup) → `data/*.csv` for the website【25†L348-L355】【7†L210-L218】.  
- **Proposed AI Agent Role:** Read Google Sheets, detect missing/incorrect entries, use web browsing & search to find and cross-check information (publisher, OA status, APCs, etc.), and write *suggestions* (with sources) back to the sheet for review.  

## Evaluating OpenClaw and Local LLMs 

Using **OpenClaw with a local LLM** is a plausible approach.  OpenClaw can run on a local machine, manage a browser tool for web automation, and call custom skills (including Google Sheets and shell commands)【12†L149-L157】【14†L279-L287】.  OpenClaw’s browser plugin allows the agent to open web pages, click, scroll, and read content in a sandboxed profile【12†L149-L152】.  Through Ollama integration, OpenClaw also offers a built-in *web search* capability to query search engines and fetch results【18†L123-L130】.  On a modern MacBook (M2, 32 GB RAM), a mid-sized local model should run; recent benchmarks suggest **Qwen 3.5** (27B parameters) as a good speed/quality trade-off (~22 GB RAM required)【17†L99-L100】【17†L113-L115】.  OpenClaw via Ollama can launch this model locally (no cloud cost or data-sharing)【17†L35-L37】【18†L113-L115】.  In short, by mid-2026 local LLMs with OpenClaw are “production-ready”【17†L33-L37】, offering offline use and no per-token fees. 

However, there are **limitations**.  Local models can handle only a limited context window (OpenClaw recommends ≥64k tokens)【18†L113-L115】.  Complex multi-step reasoning or very long text (e.g. crawling many pages for a journal) may exceed this.  The agent’s accuracy depends on model quality and clear instructions – hallucinations or mis-parsed webpages are possible.  Also, browsing real journal sites can be fragile (sites have diverse layouts, CAPTCHAs, or may block automated browsers).  OpenClaw’s browser tool uses a headless Chromium profile, which may not always retrieve all page content (and may require manual adjustment for login, cookies, etc.).  Memory and CPU will be heavily used by a large LLM plus browser sessions over hours.  Finally, setting up the Google Sheets integration requires a Google Cloud service account and careful configuration (sharing the sheet with the service account)【14†L279-L287】. 

Despite these caveats, OpenClaw’s combination of a web browser tool and Google Sheets skill matches the requirements.  Alternative strategies include writing custom Python scripts (e.g. using [BeautifulSoup](https://pola.rs) or [Selenium](https://www.selenium.dev) with an LLM via LangChain) or using cloud-based agents (e.g. GPT-4o with browsing plugins).  A pure-script approach could be simpler for debugging, but would require manually orchestrating web requests, parsing, and LLM calls.  Since the user specifically mentions OpenClaw and a local LLM, we focus on that setup, noting that frameworks like LangChain or simple Python/RPA may also work but may lack OpenClaw’s built-in agent conveniences.

## Proposed Agent Architecture

We propose the agent run as a **headless OpenClaw agent** on the Mac, scheduled to run overnight via OpenClaw’s cron jobs or the OS scheduler【22†L207-L214】.  Key components:

- **Local LLM:** Install [Ollama](https://ollama.com/) and pull a model (e.g. `qwen3.5:27b`)【17†L99-L100】【17†L113-L115】.  Configure OpenClaw (`openclaw config`) to use Ollama as the model provider (e.g. `ollama launch openclaw` or editing `openclaw.json`).  Ensure the model’s context size (256k tokens for Qwen 3.5) is sufficient for browsing tasks【18†L113-L115】.
- **OpenClaw Setup:** Install OpenClaw (`npm install -g openclaw`) or use Ollama’s integrated installer.  Enable the browser tool (`openclaw browser --browser-profile openclaw start`) and ensure web search is enabled via Ollama【18†L123-L130】.  Install or configure the [Google Sheets skill](https://github.com/openclaw/skills/tree/main/skills/google-sheet) (it requires installing a Node skill and setting the `GOOGLE_SERVICE_ACCOUNT_KEY` environment variable to a JSON key)【14†L279-L287】.
- **Data Pipeline Integration:** Use OpenClaw’s **Exec** or **CLI** tools to call existing scripts. For example, the agent can run `bash scripts/download_csv.sh` and `python scripts/update_extracted.py` from the WhereToPublish repo to refresh the raw data and see which fields remain unfilled【25†L348-L355】.  This leverages the existing pipeline logic to identify missing entries.  (Alternatively, the agent can read the processed `data/all_biology.csv` to check for empty cells in specific columns.)
- **Web Browsing & Extraction:** For each journal needing data, the agent uses the OpenClaw browser tool and web search:
  - It might query the DOAJ API or search for the journal’s homepage to confirm publisher/country.
  - To find OA status or APCs, it could search the journal website or recognized sources (Scimago, publisher pages).
  - The agent can click and scroll pages, then read text (OpenClaw’s browser can capture text or screenshots).
  - It should cross-check any finding with at least two sources when possible (e.g. if both DOAJ and the publisher’s page say “OA”, increase confidence).
- **Suggestion Output:** The agent writes suggestions back to Google Sheets.  This could be done by appending rows to a dedicated “Suggestions” tab, or by adding comment entries.  The Google Sheets skill can insert rows or write specific cell ranges【14†L279-L287】.  Each suggestion should include: the journal name (key to find the row), the field to update (e.g. “APC Euros”), the suggested value, a confidence note, and source links or quotes.  For example, a cell in “Suggestion” sheet might say: *“Journal X – APC 1500 – found on [publisher site](URL) and [OpenAPC](URL) showing avg APC ~€1500.”*

The agent should **prioritize** high-confidence fixes to avoid overwhelming the team.  For instance, only suggest an update if two independent sources agree or the model is very certain.  Low-confidence or ambiguous findings can be skipped or flagged for manual check.  This prevents noise from incomplete/corrupted scrapes.  The team can then review suggestions in the sheet and accept or reject them manually; accepted changes become part of the curated data and flow through the pipeline as usual.

## Implementation Steps

1. **Prepare Environment:** Install Ollama on the Mac and pull a suitable model (e.g. `ollama pull qwen3.5:27b`). Install OpenClaw (`npm i -g openclaw`). In Ollama, run `ollama launch openclaw` to integrate the model. Ensure Ollama’s **web_search** provider is enabled for the agent【18†L123-L130】.  
2. **Set Up Google API:** In Google Cloud Console, create a service account with the Sheets API enabled. Download the JSON key and set `GOOGLE_SERVICE_ACCOUNT_KEY=/path/key.json`. Share the target Google Sheet(s) with the service account’s email【14†L279-L287】. Install the OpenClaw Google Sheets skill (`openclaw skill install google-sheets`) and verify one can `openclaw sheets read SPREADSHEET_ID Sheet1!A1:Z10`.  
3. **Configure OpenClaw:** Use `openclaw config` to enable the `browser` and `sheets` tools. Optionally disable unnecessary plugins. Confirm `openclaw browser --status` and `openclaw sheets` commands work. Set the agent’s default model to the local Ollama model (e.g. `openclaw config set agents.defaults.model.primary ollama/qwen3.5:27b`).  
4. **Test Pipeline Execution:** As a warm-up, have OpenClaw run the existing scripts: e.g. `openclaw exec -- bash scripts/download_csv.sh` and `openclaw exec -- python scripts/update_extracted.py`. Verify `data_extracted/*.csv` appear and see which entries lack data. For instance, load `data/all_biology.csv` and identify journals with empty “APC Euros” or “Publisher” fields.  
5. **Define Agent Workflow:** Write an OpenClaw “task” or sequence for checking one field. For example, the agent could be instructed: *“For each journal where [Field] is missing, search the internet for [Field] info.”* You might script this logic in a Node/Python helper called via `openclaw exec`, or encode it as OpenClaw conversational steps with subagents.  
6. **Implement Suggestion Logic:** Use the `browser.search` (web_search) to find candidate pages, then `browser.open` to retrieve them. Use OpenClaw’s ability to extract text or take screenshots, or use the `exec` tool to fetch HTML (e.g. `curl` or Python requests). Prompt the LLM with scraped text, e.g. *“Based on the content of this page, what is the journal’s country of publication and business model?”* The LLM answers, and the agent formats that as a suggestion.  
7. **Write to Google Sheets:** With the Sheets skill, append each suggestion. For example: 
   ```
   openclaw sheets append SPREADSHEET_ID "Suggestions!A:D" '[["Journal Name","APC (€) Suggestion","Source","Confidence"]]`
   ``` 
   This requires crafting the JSON array correctly. Alternatively, have a dedicated Google form or sheet for suggestions.  
8. **Human Review Interface:** Ensure the output (new sheet or columns) is easy to review. Possibly color-highlight or sort by confidence. Team members then copy accepted suggestions into the main sheet or mark them done.  
9. **Schedule Nightly Runs:** Use OpenClaw’s cron mechanism (`openclaw cron create ...`) or macOS `launchd` to run the agent script at night. Each run should be isolated (so context/history is fresh) and should log its actions. OpenClaw’s tasks system will record successes/failures【22†L207-L214】. Check that the Mac does not sleep during the run.  
10. **Testing and Iteration:** Start with a small subset (e.g. one field or one subject area) to refine prompts and extraction code. Monitor the agent’s suggestion accuracy and refine. Limit output to the “most important” missing fields or highest-confidence items to avoid overload.

## Potential Challenges and Mitigations

- **Incorrect or Incomplete Data:** Web pages may not clearly state needed info, or the agent might misinterpret HTML. *Mitigation:* Require multiple sources or confidence scoring; flag uncertain cases for manual research.  
- **Overwhelming Volume:** If the agent suggests too many changes, reviewers will be overwhelmed. *Mitigation:* Filter to the highest-impact fields (e.g. fields crucial for searchability or compliance) and highest-confidence hits. Possibly limit suggestions per journal or per run.  
- **Model Limitations:** A local LLM may struggle with very long or complex tasks. It may “forget” earlier steps if the conversation is long. *Mitigation:* Break tasks into smaller chunks (e.g. one field per sub-agent). Use system messages to anchor tasks. Ensure the prompt includes only relevant text excerpts.  
- **Rate Limits and Blocks:** Automated browsing could trigger rate limits or CAPTCHAs on publisher or DOAJ sites. *Mitigation:* Respect robots.txt where possible, throttle requests, and handle HTTP errors gracefully. If blocked, skip that journal.  
- **Data Consistency:** If the sheet data is updated concurrently by human editors, the agent’s suggestions could be stale. *Mitigation:* Ideally pause editing during the agent run or snapshot the sheet at the run’s start.  
- **Security/Privacy:** Granting API access to a service account is sensitive. Keep credentials secure and use read-only where possible. The agent will have write access to sheets, so ensure only it (and authorized humans) can modify those.  

No approach is fully automatic here. The agent must **explain its reasoning** (we recommend that each suggestion string includes the source URLs and a short rationale) so maintainers can trust or reject it. By design, all AI-suggested updates are **reviewed by humans** before acceptance, preventing unverified data from entering the official database. 

In summary, using OpenClaw with a local LLM and the Google Sheets API is feasible and aligns with 2026-era capabilities【17†L33-L37】【12†L149-L152】.  Key steps include environment setup (Ollama/OpenClaw), connecting to Google Sheets【14†L279-L287】, scripting the agent’s web-browsing and extraction logic, and iteratively testing on a small dataset.  Challenges include managing model context size, ensuring data accuracy, and avoiding too many low-confidence suggestions. With careful configuration and human oversight, such an agent could incrementally **complement** the existing pipeline by catching gaps that the current automated joins miss, improving the database quality over time.
